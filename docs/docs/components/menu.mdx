# Menu

A menu shows a list of choices on a temporary surface, anchored to the control that opened it.
It follows the [Material Design 3 Menu](https://m3.material.io/components/menus/overview) specification.

Menu renders through [Portal](./portal.mdx), so wrap your app in a `PortalHost` once at the
root. It claims the `PORTAL_LAYERS.menu` layer, which puts it above bottom sheets, dialogs, and
snackbars. A menu can open from any of them.

## Usage

Pass the trigger as `anchor` and the choices as children. With no `visible` prop, Menu manages
its own open state. It hooks the press of the anchor to open, and closes on an outside press, an
item press, or the Android back button.

<SnackExample
  name="Root Native Menu — Usage"
  code={`
  import { IconButton, Menu, PortalHost } from '@rootnative/components'
  import { mdiResolver } from '@rootnative/components/mdi'
  import { ThemeProvider } from '@rootnative/core'
  import { SafeAreaProvider } from 'react-native-safe-area-context'
  import { useState } from 'react'
  import { Text, View } from 'react-native'

  function Screen() {
    const [last, setLast] = useState('nothing yet')
    return (
      <View style={{ flex: 1, alignItems: 'center', justifyContent: 'center', gap: 16 }}>
        <Text>Last action: {last}</Text>
        <Menu
          align="end"
          anchor={<IconButton icon="dots-vertical" accessibilityLabel="More actions" />}
        >
          <Menu.Item label="Edit" leadingIcon="pencil-outline" onPress={() => setLast('Edit')} />
          <Menu.Item label="Duplicate" leadingIcon="content-copy" onPress={() => setLast('Duplicate')} />
          <Menu.Item label="Delete" leadingIcon="trash-can-outline" onPress={() => setLast('Delete')} />
        </Menu>
      </View>
    )
  }

  export default function App() {
    return (
      <SafeAreaProvider>
        <ThemeProvider iconResolver={mdiResolver}>
          <PortalHost>
            <Screen />
          </PortalHost>
        </ThemeProvider>
      </SafeAreaProvider>
    )
  }
`}
/>

The anchor renders where the `<Menu>` sits in your tree, wrapped in a measuring `View`. In
self-managing mode it must be a single element that accepts `onPress`. Every Root Native
pressable does. Its own `onPress` still fires.

## Controlled

Pass `visible` and `onDismiss` to drive the visibility yourself. Menu then never toggles
itself. You wire the press of the anchor, and `onDismiss` fires for an outside press, an item
press, and Android back.

<SnackExample
  name="Root Native Menu — Controlled"
  code={`
  import { Button, Divider, Menu, PortalHost } from '@rootnative/components'
  import { mdiResolver } from '@rootnative/components/mdi'
  import { ThemeProvider } from '@rootnative/core'
  import { SafeAreaProvider } from 'react-native-safe-area-context'
  import { useState } from 'react'
  import { View } from 'react-native'

  const SORTS = ['Name', 'Date modified', 'Size']

  function Screen() {
    const [open, setOpen] = useState(false)
    const [sort, setSort] = useState('Name')
    return (
      <View style={{ flex: 1, alignItems: 'center', justifyContent: 'center' }}>
        <Menu
          visible={open}
          onDismiss={() => setOpen(false)}
          anchor={
            <Button variant="outlined" trailingIcon="chevron-down" onPress={() => setOpen(true)}>
              {\`Sort: \${sort}\`}
            </Button>
          }
        >
          {SORTS.map((option) => (
            <Menu.Item
              key={option}
              label={option}
              selected={option === sort}
              leadingIcon={option === sort ? 'check' : undefined}
              closeOnPress={false}
              onPress={() => setSort(option)}
            />
          ))}
          <Divider />
          <Menu.Item label="Done" onPress={() => setOpen(false)} />
        </Menu>
      </View>
    )
  }

  export default function App() {
    return (
      <SafeAreaProvider>
        <ThemeProvider iconResolver={mdiResolver}>
          <PortalHost>
            <Screen />
          </PortalHost>
        </ThemeProvider>
      </SafeAreaProvider>
    )
  }
`}
/>

## Items

`Menu.Item` renders a leading icon, a label, trailing text, and a trailing icon. All are
optional except the label. Anything else you put in a Menu renders as given. That is how a
[`Divider`](./divider.mdx) groups items.

| Prop | Renders |
|------|---------|
| `label` | `labelLarge` / `onSurface`, truncated to one line |
| `leadingIcon` | 24dp / `onSurfaceVariant` |
| `trailingText` | `labelLarge` / `onSurfaceVariant`: a keyboard shortcut or a short status |
| `trailingIcon` | 24dp / `onSurfaceVariant` |
| `disabled` | The label and both icons dim together at 38% opacity, and keep their own colors. The item stops responding |
| `selected` | One choice of a single-choice group. `true` gives the item a `secondaryContainer` background, and `onSecondaryContainer` for the label, the icons, and the trailing text. A [vertical menu](#vertical-menu) uses its own colors |
| `checked` | An on/off setting. The same colors as `selected` |

**An item press closes the menu.** Set `closeOnPress={false}` on an item that toggles something
and must stay open, such as a sort choice or a "show hidden files" switch.

### Selected and checked items

Use `selected` for a choice, such as a sort order, and `checked` for an on/off setting. An item
takes one of the two. The type rejects both together. Both are controlled only: the items
unmount when the menu closes, so you keep the state and change it in `onPress`.

```tsx
{SORTS.map((option) => (
  <Menu.Item
    key={option}
    label={option}
    selected={option === sort}
    closeOnPress={false}
    onPress={() => setSort(option)}
  />
))}
<Divider />
<Menu.Item
  label="Show hidden files"
  checked={showHidden}
  closeOnPress={false}
  onPress={() => setShowHidden(!showHidden)}
/>
```

Set `selected` on every item of a group, `false` on the others, so a screen reader hears each
one as a choice. The selected colors are the only mark that MD3 draws. Add a `check` icon
when the difference must not rest on color alone.

A disabled selected or checked item keeps the plain colors at 38% opacity, on a 12% `onSurface`
background, and a screen reader still hears its state.

## Vertical menu

`variant="vertical"` gives the MD3 Expressive vertical menu. The default, `'baseline'`, is the
original MD3 menu.

```tsx
<Menu variant="vertical" anchor={anchor}>
  <Menu.Item label="Edit" leadingIcon="pencil-outline" onPress={edit} />
  <Menu.Item label="Duplicate" leadingIcon="content-copy" onPress={duplicate} />
  <Menu.Item label="Delete" leadingIcon="trash-can-outline" onPress={remove} />
</Menu>
```

| Part | Baseline | Vertical |
|------|----------|----------|
| Container | `surfaceContainer`, corner 4dp | `surfaceContainerLow`, corner 16dp |
| Block padding | 8dp | 2dp |
| Item | Spans the full width, 48dp minimum height | 4dp in from each side, 44dp minimum height |
| Item corners | None | 12dp on the outer corners of the first and the last item, 4dp on the others |
| Label | `labelLarge` | `bodyLarge` |
| Leading / trailing icon | 24dp | 20dp |
| Trailing text | `labelLarge` | `labelSmall` |
| Selected or checked item | `secondaryContainer`, `onSecondaryContainer` content | `tertiaryContainer`, `onTertiaryContainer` content, 12dp corners on every side |
| Disabled selected item | Plain colors at 38% on 12% `onSurface` | `tertiaryContainer` and `onTertiaryContainer`, both at 38% |
| Disabled item content | Its own colors at 38% | `onSurface` at 38% |

The menu finds the place of each item to set its corners. It sees an item that is a direct
child, in an array from `.map`, or in a fragment. An item inside a component of your own takes
the 4dp corners.

When an item becomes selected, its corners morph to 12dp on `springFastSpatial`. Reduced motion
cuts the morph.

### Groups

`Menu.Group` splits a vertical menu into groups. A group takes an optional `label`.

```tsx
<Menu variant="vertical" anchor={anchor}>
  <Menu.Group label="Sort by">
    <Menu.Item label="Name" selected={sort === 'name'} onPress={() => setSort('name')} />
    <Menu.Item label="Size" selected={sort === 'size'} onPress={() => setSort('size')} />
  </Menu.Group>
  <Menu.Group>
    <Menu.Item label="Show hidden files" checked={showHidden} onPress={toggleHidden} />
  </Menu.Group>
</Menu>
```

| Part | Value |
|------|-------|
| Group | `surfaceContainerLow`, elevation level 2, 2dp block padding |
| Gap between groups | 2dp |
| First group | 16dp top corners, 8dp bottom corners |
| Middle group | 8dp corners |
| Last group | 8dp top corners, 16dp bottom corners |
| Label | `labelLarge` / `onSurface`, 32dp minimum height, 12dp start and 4dp end padding |

With two or more groups, each group draws its own surface, and the menu surface is a clear
column. With one group, the menu surface is the group. The items of each group get their
corners from their place in that group.

The menu sees a group that is a direct child, in an array, or in a fragment. Children outside a
`Menu.Group` form a group of their own, so each item is on a group surface.

`Menu.Group` works in a vertical menu only. The MD3 baseline menu has no groups, so a baseline
menu renders the children of a group with no label, and warns in development.

## Placement

`side` and `align` are preferences, not commands.

| Prop | Values | Default | Meaning |
|------|--------|---------|---------|
| `side` | `'bottom' \| 'top'` | `'bottom'` | Which side of the anchor the menu prefers |
| `align` | `'start' \| 'center' \| 'end'` | `'start'` | Cross-axis alignment against the anchor |
| `offset` | `number` | `0` | Gap between the anchor edge and the menu, in dp |
| `screenMargin` | `number` | `8` | Minimum distance the menu keeps from every screen edge. The edges are inside the safe-area insets |
| `maxHeight` | `number` | — | Caps the height of the menu in dp. The menu scrolls past it |

`align` is **logical**: `'start'` is the left edge of the anchor in LTR and its right edge in RTL.

A menu that doesn't fit on its preferred side flips to the other side, but only when that side
has more room. A flip into a side with the same room only moves the clipping. Horizontally, the
menu shifts back inside the margin instead of a flip. When neither side has room for the whole
menu, it caps at the available height and scrolls.

The menu positions itself from the window coordinates of the anchor, measured when it opens.
It doesn't follow the anchor while a scroll view moves under it. A close and a reopen measure
again.

### Height

A menu never exceeds the space available on the side it resolved to. Anything past that would
put items where nobody can see them. When the items don't fit, the menu caps at that space and
scrolls.

`maxHeight` caps it sooner. It is a cap, not an override. It only ever makes the menu shorter,
and the menu ignores a value larger than the available space.

```tsx
{/* 30 items with room for all of them is a wall of text; 280dp reads better */}
<Menu maxHeight={280} anchor={anchor}>
  {options.map((option) => (
    <Menu.Item key={option} label={option} onPress={() => select(option)} />
  ))}
</Menu>
```

The placement decision includes the cap, and doesn't apply it after. So a menu that fits below
the anchor *once capped* stays below it, and doesn't flip above because of its uncapped height.

### The menu is confined to its PortalHost

You can see a menu only inside the overlay layer it renders into, so the menu fits itself to
that layer, not to the window. A `PortalHost` mounted *inside* a screen, below an app bar or
above a bottom navigation, gives a layer shorter than the window. A tall menu then caps at the
edge of the layer, and doesn't reach past it into a region that the layer would clip.

That is why the root of your app is the right place for `PortalHost`. It gives a menu the whole
window. If you mount one per screen, a menu near the bottom of a long list has much less room
to open into.

## Overrides

| Prop | Target |
|------|--------|
| `containerColor` | The menu surface background. In a vertical menu of two or more groups, the background of each group |
| `style` | The menu surface. In a vertical menu of two or more groups, the clear column that holds the groups |
| `anchorStyle` | The `View` wrapping the anchor |
| `Menu.Group` `style` | The group. In a menu of two or more groups, the group surface |
| `Menu.Item` `containerColor` | The item background, also on a selected or checked item. The hover, press and focus layers derive from it again |
| `Menu.Item` `contentColor` | The label, both icons, and the trailing text of the item, also on a selected or checked item |
| `Menu.Item` `labelStyle` | The label `Text` only. It doesn't affect the icons |

`contentColor` on an item is how a destructive choice gets the `error` color:

```tsx
<Menu.Item label="Delete" leadingIcon="trash-can-outline" contentColor={theme.colors.error} />
```

A disabled item always uses the MD3 disabled treatment. Neither override changes that.

## Tokens

| Token | Value |
|-------|-------|
| Container | `surfaceContainer`, corner 4dp (`cornerExtraSmall`), elevation level 2 |
| Width | As wide as the widest item, min 112dp, max 280dp |
| Block padding | 8dp, inside the scroll area |
| Item height | 48dp minimum |
| Item padding | 12dp horizontal, 12dp between icon, label, and trailing content |
| Item label | `labelLarge` / `onSurface` |
| Leading / trailing icon | 24dp / `onSurfaceVariant` |
| Selected or checked item | `secondaryContainer`, with `onSecondaryContainer` for the label and the icons |
| Scrim | None. An MD3 menu doesn't dim what is behind it |

These are the baseline tokens. The [vertical menu](#vertical-menu) table gives the other variant.

## Motion

The menu scales in from 80% and fades on `springFastSpatial`. It grows out of the corner nearest
the anchor, through `transformOrigin`. Both collapse to a hard cut under reduced motion; see
[Motion](../motion.md).

The surface stays invisible for the frame between the mount and the measurement. Its own size
decides which side it lands on, so the layout must run before the placement.

## Accessibility

- The surface reports `role="menu"`, and each item reports `role="menuitem"`.
- A `selected` or `checked` item reports its state through `aria-checked`. On web, a `selected`
  item is a `menuitemradio` and a `checked` item a `menuitemcheckbox`. Native keeps `menuitem`,
  and TalkBack and VoiceOver read the checked state from `aria-checked`.
- An item exposes `accessibilityState.disabled`.
- On web, a `Menu.Group` reports `role="group"`, and its `label` is the name of the group. The
  label text itself is hidden from the screen reader, so it isn't read twice. On native, the
  screen reader reads the label as text before the items of the group.
- The anchor is annotated for you, in both the controlled and the uncontrolled form: `aria-haspopup="menu"` plus an `aria-expanded` that follows the menu. So a screen reader announces the trigger as a control that opens a menu, not as a plain button.
- **On web**, focus moves into the menu when it opens, Arrow Down/Up and Tab move between the items, Escape dismisses, and focus returns to the anchor on close. See [Accessibility](../accessibility.md#dialogs-menus-and-sheets-on-web). The surface is *not* marked modal on native, on purpose. A modal mark would also take the dismiss region below out of the accessibility tree.
- The region that catches outside presses announces as a button labelled "Close menu". Override it with `dismissAccessibilityLabel`. An MD3 menu has no scrim, so this region is transparent. It exists to catch outside presses and to give a screen reader a way out.
- On web, an item shows a keyboard focus ring (`secondary`, 3dp), driven by the same focus-visible state as the rest of the library.
