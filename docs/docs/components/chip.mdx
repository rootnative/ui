# Chip

Chips help people enter information, make selections, filter content, or trigger actions.
The component follows the [Material Design 3 Chip](https://m3.material.io/components/chips/overview) specification.

## Usage

<SnackExample
  name="RootNative Chip — Usage"
  code={`
  import { Chip } from '@rootnative/components'
  import { mdiResolver } from '@rootnative/components/mdi'
  import { ThemeProvider } from '@rootnative/core'
  import { SafeAreaProvider } from 'react-native-safe-area-context'
  import { Alert, View } from 'react-native'

  export default function App() {
    return (
      <SafeAreaProvider>
        <ThemeProvider iconResolver={mdiResolver}>
          <View style={{ flex: 1, alignItems: 'center', justifyContent: 'center' }}>
            <Chip variant="assist" onPress={() => Alert.alert('Pressed')}>
              Assist
            </Chip>
          </View>
        </ThemeProvider>
      </SafeAreaProvider>
    )
  }
`}
/>

## Variants

| Variant | Use case |
|---------|----------|
| `assist` | Smart or automated actions |
| `filter` | Filter content, toggle on/off |
| `input` | Information that the user entered, such as tags |
| `suggestion` | Dynamic suggestions |

## Elevated

Available on the `assist`, `filter`, and `suggestion` variants. An input chip is always outlined, so `elevated` is not one of its props. TypeScript rejects `<Chip variant="input" elevated>`, and doesn't ignore it.

  name="RootNative Chip — Elevated"

## Filter Chips

A filter chip supports a `selected` state. When it is selected, the chip shows
a check mark icon. `selected` with `onSelectedChange` is the controlled
form. `defaultSelected` is the uncontrolled form: the chip flips its own state
on press and reports the new state through `onSelectedChange`.

<SnackExample
  name="RootNative Chip — Filter"
  code={`
  import { Chip } from '@rootnative/components'
  import { mdiResolver } from '@rootnative/components/mdi'
  import { ThemeProvider } from '@rootnative/core'
  import { SafeAreaProvider } from 'react-native-safe-area-context'
  import { useState } from 'react'
  import { View } from 'react-native'

  export default function App() {
    const [active, setActive] = useState(true)
    const [inactive, setInactive] = useState(false)
    return (
      <SafeAreaProvider>
        <ThemeProvider iconResolver={mdiResolver}>
          <View style={{ flex: 1, flexDirection: 'row', alignItems: 'center', justifyContent: 'center', gap: 8 }}>
            <Chip variant="filter" selected={active} onSelectedChange={setActive}>Active</Chip>
            <Chip variant="filter" selected={inactive} onSelectedChange={setInactive}>Inactive</Chip>
          </View>
        </ThemeProvider>
      </SafeAreaProvider>
    )
  }
`}
/>

## Close / Remove

Pass `onClose` to show a trailing close icon. It renders only on the `input` variant, and on the `filter` variant when the chip is selected.

The close icon is an accessibility target separate from the chip, so it names itself `Remove {label}`, not a bare "Remove". A screen-reader user hears which chip they are about to remove. Override the whole string with `closeAccessibilityLabel` when you localize.

<SnackExample
  name="RootNative Chip — Close"
  code={`
  import { Chip } from '@rootnative/components'
  import { mdiResolver } from '@rootnative/components/mdi'
  import { ThemeProvider } from '@rootnative/core'
  import { SafeAreaProvider } from 'react-native-safe-area-context'
  import { Alert, View } from 'react-native'

  export default function App() {
    return (
      <SafeAreaProvider>
        <ThemeProvider iconResolver={mdiResolver}>
          <View style={{ flex: 1, flexDirection: 'row', alignItems: 'center', justifyContent: 'center', gap: 8 }}>
            <Chip variant="input" onClose={() => Alert.alert('Closed')}>Tag</Chip>
            <Chip variant="filter" selected onClose={() => Alert.alert('Closed')}>Active</Chip>
          </View>
        </ThemeProvider>
      </SafeAreaProvider>
    )
  }
`}
/>

## Avatar

The `input` variant supports a custom `avatar` prop. `avatar` and `leadingIcon` are mutually exclusive on this variant. TypeScript rejects both together.

<SnackExample
  name="RootNative Chip — Avatar"
  code={`
  import { Chip } from '@rootnative/components'
  import { mdiResolver } from '@rootnative/components/mdi'
  import { ThemeProvider } from '@rootnative/core'
  import { SafeAreaProvider } from 'react-native-safe-area-context'
  import { Image, View } from 'react-native'

  export default function App() {
    return (
      <SafeAreaProvider>
        <ThemeProvider iconResolver={mdiResolver}>
          <View style={{ flex: 1, alignItems: 'center', justifyContent: 'center' }}>
            <Chip
              variant="input"
              avatar={
                <Image
                  source={{ uri: 'https://i.pravatar.cc/40' }}
                  style={{ width: 24, height: 24, borderRadius: 12 }}
                />
              }
              onClose={() => {}}
            >
              John Doe
            </Chip>
          </View>
        </ThemeProvider>
      </SafeAreaProvider>
    )
  }
`}
/>

## A chip with no action

A chip is a button only when a press does something. An assist, suggestion or
input chip with no `onPress`, no `onLongPress` and no `href` renders as a
static label. It has no button role, no tab stop, no hover layer and no
pointer cursor. A screen reader reads its text, and a keyboard user doesn't
stop on it. An input chip with only `onClose` keeps its close button.

```tsx
<Chip leadingIcon="language-typescript">TypeScript-first</Chip>
```

A filter chip is always a button, because a press toggles it.

A chip inside the `<Link asChild>` of Expo Router stays a button with no `onPress`
of its own. `Link` gives it an `href`, and on the web the chip renders as an
`<a href>`.
